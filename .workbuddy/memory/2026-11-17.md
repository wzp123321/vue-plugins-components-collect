- 现象：hover 数据行时浅蓝条带横向落在 D 列附近（应从 A 列起）、纵向偏下约两行，与鼠标所在行对不上。
- 根因（CDP 实测定位）：条带 `position:fixed`，style 是 `translate(336px,204px)`，但 `getBoundingClientRect()` 却是 `(611,283)`，差值 `(275,79)` 恰等于祖先 `.pcv-wrap` 的 rect 原点。外壳 `common-page-container.vue` 的 `.pcv-wrap` 带 `backdrop-filter:blur(20px)`——按 CSS 规范它会为 `position:fixed` 后代建立包含块，导致条带再按 .pcv-wrap 原点偏移一次。坐标计算本身没错。
- 修复：`univer-entry.vue` 把 `.ue-rowhover` 包进 `<Teleport to="body">`，让 fixed 以视口为基准，与 `outer.top/left + cellRect` 口径一致。实测 rect 回到 `(336,204)`，与 A 列对齐。只改页面文件，未动全局组件。
- 通用坑（本项目适用）：外壳 `.pcv-wrap` 的 backdrop-filter 会劫持所有 `position:fixed` 后代的包含块；页面内要做视口级 fixed 浮层，一律 Teleport 到 body。

## Univer 录入台「默认高亮边框」定位并修复

- 现象：进 Univer BI 录入台，数据区被一圈蓝框围住（右+下两条边可见），清空选区也消不掉。
- 根因：`SheetsFilterRenderController._renderRange` 用 **`SelectionControl`（画选区那套控件）** 把 filterModel 的 range 描一圈边。而 `ensureFilter` 原来按「表头 + 已有数据行 + 有表头的列」建 range → 空表一进页面就有框，且随数据行数长大。与 selection 无关（`getActiveRange()` 为 null 时框仍在）。
- 修复：`ensureFilter()` 去掉 colCount 参数，range 固定为整表 `getRange(0,0,SHEET_ROW_COUNT,SHEET_COLUMN_COUNT).createFilter()`。右/下边落到视口外，可视区内无框；已存在的窄 filter 自动升级（不满足整表就 remove 重建）。
- 已知代价：`_renderButtons` 对 range 内每一列都 createInstance 漏斗，空列（H 之后）也带浅灰漏斗，Univer 无逐列开关。隐藏空列可消漏斗，但会让粘贴越过 defs 的数据写进隐藏列，风险更大 → 不采用。
- 排查手法（可复用）：CDP + `Page.addScriptToEvaluateOnNewDocument` hook `CanvasRenderingContext2D.prototype` 的 stroke/fill 记录 style+stack；再配合 `filter.remove()` / `createFilter()` A/B 截图与蓝色像素计数定位到 filter range。
- 临时暴露 `window.__univerApi` 调试后已删除。

## Univer 行 hover 高亮（useEntrySheet + univer-entry）

- Univer 无行级 hover，画布上也没有可测量行 DOM → 页面叠一层 `position:fixed` 条带（pointer-events:none）。
- 几何由 `useEntrySheet.paintRowHover` 算：`getCellRect()` 是**画布内容坐标**（加容器 rect 才是视口），且**多列区间只返回左上那一格** —— 宽度要用「首列 left / 末列 right」两次取值拼。
- 找行走对 `getCellRect(row,0)` 的 top/bottom 二分（≤15 次），不用行高×行号自算：滚动/冻结/隐藏行/自定义行高全自适应；滚轮时直接清空等下次 pointermove 重算。
- 底色 `color-mix(primary 6%, panel)`，暗色 10%（--bi-hover 在亮色 #f7f9fc 压白格几乎看不见）。

## 打包分包重设计（vite.config.ts manualChunks）

- 背景：已有成型分包，但 `univer-entry` 单块 7.5MB（@univerjs 全家 + react peer 无规则直落页面块），`@antv` 只匹配 g6 主包致 g6-pc 散落、antv-g6 成兜底大杂烩，vtable/xlsx/exceljs 无规则。
- 新分组：vue 核心同组（硬约束）｜ univer 全家+React 运行时(cmdk/sonner/react-*/use-*)封闭同组 ｜ rxjs **独立**（antv 页与 univer 共用，并入任一组都会拖整组）｜ @visactor **全合并**（vchart/vtable 共享 vrender/vutils 底层，拆开有跨组循环风险）｜ @antv 全 scope ｜ xlsx+exceljs→sheet-io ｜ 重型库各自组。通用小依赖（dayjs/lodash-es/vue-router/vuedraggable）交 rollup 自动，不设通用兜底组（会与 vue-vendor 成环）。
- 关键依赖事实：`@univerjs/preset-sheets-core` peer react/react-dom/rxjs；rxjs 被 antv-g6 service 直接 import；react 消费者全是 univer UI 链。
- 验证：ts-check 通过；抽真实 manualChunks 函数做包归属模拟全符合预期；check:nav / check-unresolved-components 均 OK。**eslint 对 vite.config.ts 崩在 `import/no-cycle` 解析 rollup-plugin-visualizer 的 exports，HEAD 基线同样 exit=2，与本改动无关**。本机 build 仍受守卫限制无法跑（dist 是残骸，无 index.html、hash 对不上）。
