## eslint 存量 error 归零：vue-eslint-parser 对裸 HTML 误报

- 现象：`collect/src/demo/promise/test.html:33` 报 `vue/comment-directive`（message 只有 "clear"），是全仓唯一 error。
- 根因：该文件是**裸 HTML + 内联 script** 的浏览器试验页（手写 Promise 练习，`<script src>` 直接引入同目录 js），全仓无任何引用。`parser: vue-eslint-parser` 把它当 SFC 解析，走到 `</html>` 时指令栈 clear 断言失败 → 误报。
- 处理：按项目既有约定（同 `src/assets/iconfont-symbol.js` 的处理）在 `collect/.eslintignore` 追加 `src/demo/**/*.html` 并写明理由。全量 eslint 结果：**0 error / 400 warning**。
- **未删文件**：`src/demo/promise/` 三个文件（test.html / index-common.js / index-es.js）全仓无引用，属学习残留，可整目录删除，但需用户确认。

## 坑：`.git/index.lock` 残留 + git 僵尸进程

- 现象：`git add` 报 `Unable to create '.git/index.lock': File exists`，实际没有任何真实 git 操作在跑。
- 特征：`tasklist` 里十几个 `git.exe`，WorkingSet 全部 12K、`StartTime`/`Path` 均为空 —— 是此前被 SIGTERM 中断的命令（如 `git status --ignored`）留下的僵尸进程，不是活进程。
- 处理：确认 lock 文件为 **0 字节**后直接 `rm -f .git/index.lock` 即可恢复，无需杀进程。
- 结论：以后再遇 lock 报错，先 `ls -la .git/index.lock` 看大小 + 查进程内存，别急着杀进程。
