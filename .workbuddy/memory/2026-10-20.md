### 格式刷自动应用的选择区竞态（本日核心实证）
- Chrome 原生双击选词发生在 mousedown 默认动作里，但 `selectionchange` → `DOMObserver.flush()` 同步进 PM state 是异步的，实测晚于紧随的 rAF 一帧以上（mouseup 当时 state 可能还是旧选区）。直接应用会把格式打到旧选区（如采样词自己）。
- 三击无此问题：PM `defaultTripleClick` 在 mousedown 时同步 setSelection 且 preventDefault（源码 prosemirror-view 1.42.6 `handlers.mousedown` → `handleTripleClick` 兜底）。
- 双击无插件认领 `handleDoubleClick` → 不 preventDefault → 选词全靠 Chrome 原生。
- 修复方案（已验证）：mousedown 时记录旧选区 anchor/head，mouseup 后有界重试（≤10 帧）——选区非空且相对 mousedown 发生变化才 applyFormat；始终未变（普通单击）则放弃、保持激活态。实测 mousedown handleDOMEvent 确实被调用（无 someProp 短路：formatPainter 插件顺序在 table 三件套之前）。
- PM 事件通路（源码级）：mousedown 是内置 handler → 合并监听 = eventBelongsToView → runCustomHandler(someProp 首个 truthy 即停) → 内置 handler；mouseup 非内置 → ensureListeners 独立监听（无 eventBelongsToView 门控）。`view.domObserver.flush()` 可主动同步 DOM 选区进 state（readDOMChange from<0 时 setSelection  dispatch），但 domObserver 不在公开类型里。

### CDP 合成事件语义（E2E 点击模拟必守）
- `Input.dispatchMouseEvent` 的 clickCount 即 `MouseEvent.detail`，Chrome 只认 detail：单击=clickCount:1；真实双击=press(1)+press(2)（第二次带 clickCount:2 → click+click+dblclick）；三击=press(1)+press(2)+press(3)。**两次 clickCount:1 既不发 dblclick 也不原生选词**（这是早先 E2E 格式刷全失败的直接原因）。
- 按钮上：2×clickCount:1 只有 click×2；1×clickCount:2 是 click+dblclick（Vue 下会激活→取消，进不了连续模式）。
- **编辑器内点击落点必须落在文字上**：块级元素几何中心是整行宽度中点、位于文字右侧空白区，双击只选中不含文字的结构边界范围（blockquote 实测 132→135，textBetween=" "），setMark 无可作用文本、strong 数不变——是测试落点问题不是产品 bug。用 `document.createRange` 覆盖文字片段取中心点，且偏移量要按当前文本节点长度钳制（加粗会拆短文本节点："引用块："+strong+剩余，setEnd 越界抛 IndexSizeError）。
- 每次点击前重新取坐标：scrollIntoView / 选中文本滚动 / focus scrollIntoView 都会让旧坐标失效。

## 2026-10-20 下午 3D 地图：控制台限高 + 右栏重排 + 飞线缩小时断线的根因

- 飞线「缩小后一截一截」根因：ribbon 线宽写死在世界单位（拖尾 0.66 / 轨道 0.34），
  屏幕宽度 = 世界宽 × 视口高 /（2·tan(fov/2)·视距）。fov=32°、视口高约 800px 时，
  视距 330 → 拖尾 3.1px；视距 690（最远）→ 1.5px，轨道只剩 0.77px。
  不足 1 像素 + 本工程走 EffectComposer（renderTarget samples=0，没有 MSAA）→
  片元覆盖率不稳定：有的段画得出、有的整段丢，于是断成一节一节；轨道与拖尾宽度不同、
  断点位置也不同，看起来就像「错位」。放大时线宽 3px 以上覆盖率稳定，所以很流畅。
- 修法（不改观感、只兜底）：给半宽加「屏幕像素下限」。
  `useMapViewport` 的 Tick 增加第 3 个参数 `ViewportMetrics{width,height,pixelRatio}`
  （旧回调不用改，向后兼容）；`useFlyLines.tick` 按每条线中点到相机的距离算 worldPerPx
  传给 `updateFlyLine`；下限 MIN_STREAK_PX=2 / MIN_TRACK_PX=1.2 / MIN_HEAD_PX=6。
  拉近时下限不生效，渲染结果与改前一致。
- 布局：右栏 `.china3d-rail`（top18 / right18 / bottom68 / 宽 300，flex column，gap10）
  统一收控制台 + 区域详情 + 数据看板。控制台 max-height 36% + `__body` 内部滚动；
  详情 `flex:1 1 0; min-height:130`；看板 max-height 30%。
  ⚠️ 详情「折叠态贴底」的 `margin-top:auto` 只能写在 `.map-detail--collapsed` 里，
  写在展开态会被 auto margin 抢走空间、`flex-grow` 直接失效。
- 左下角 `.map-left-rail`（饼图 + 图例，left16 / bottom18 / gap10）取代各自写死的
  `bottom:150` / `bottom:22`（原来左边缘还差 6px）。
- 底部停靠条：时间轴（原 bottom18 居中 720 宽）会同时压到右栏与左下角图例，改成
  `left: calc(50% - var(--rail-shift,0px))` + `width: min(700px, 100% - 440px)`，
  `--rail-shift:110px` 在页面根节点定义；面包屑 MapNavBar `bottom:22 → 130`
  （原来直接压在时间轴上），stage-host `26 → 130`、`--raised 96 → 216`（让开 74 高的面包屑）。
- 落点：`useMapViewport.ts` / `useFlyLines.ts` / `drawFlyLine.ts` /
