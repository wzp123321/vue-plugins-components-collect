## 右键菜单"字小了框还巨大"的真正根因（本仓特有）
- CDP 实测 .univer-popup 面板：菜单项高 68px、面板宽 277px、容器 gap 19.5px，但 font-size 12.5px —— 字号被压住、rem 间距没压住。
- 根因：`assets/css/common.less` 的大屏模板 `:root { font-size: calc(100vh / 10.8) }` 把根字号顶到 **78.1481px**，Univer 的 Tailwind 全用 rem，所有 gap/padding/min-w/size 被放大 ~4.88 倍（`gap-1` = 0.25rem = 19.537px，精确吻合）。rem 恒相对根 html，压容器 font-size 无效。
- 修法：进页 `documentElement.classList.add('univer-normal-rem')` + `html.univer-normal-rem{font-size:16px}`，离开移除。实测根字号 16px 后：菜单 277×828 → **184×301**，项高 68→24px，gap 19.5→4px，位置对准鼠标；侧边栏/表格布局无变化（本页与外壳全 px，源码 rem 仅 6 处且是 demo 页）。
- 另一处纠错：真实弹层是 `<section class="univer-popup univer-fixed">` 挂 body 下，`.univer-popup` 类是有效的；`#univer-popup-portal-*` 是**空容器（0 子节点）**，此前按它写的选择器全是死代码，已清掉。
- 方法教训：这类问题必须起 dev server + CDP 抓真实 DOM/computed style，纯看源码会反复猜错（前一版两次"修复"都是死代码）。

## 暗黑模式表格仍白底 —— 真正根因（反色机制，前面两次都改反了）
- 用户二次反馈"暗黑下表格还是白"，这次起 dev server + CDP 实测坐实：`setDark` 确实执行成功（日志 `gray0=#16191f`），但画布是 `rgb(242,243,245)`。

- 连带修正：`writeHeader` 原来按 `html.dark` 写 `#20242c`，会被反转成亮色 → 改为恒写 `HEADER_BG_LIGHT='#f1f4fb'`（提到 schema.ts 常量）。移除 `darkBlueTheme`/`BRAND_PRIMARY_DARK`/`GRAY_DARK_OVERRIDE`。

## 暗色行 hover 修复（vxe / VTable）
- 现象：vxe 暗色下 hover 一行出现**整条白带**、字几乎看不见；VTable 整行发蓝太跳。

## vxe 列筛选面板提示被裁（2026-11-02 修）
- 症状：`.dt-filter-hint` 那行「文本/日期按包含匹配…支持 >=30 …」被弹层右侧裁掉。
- 根因：全站有一条 `* { white-space: nowrap }`，它**直接**作用到每个元素，优先级高于继承 —— 只在 `.dt-filter-panel` 写 normal 传不下去，`.dt-filter-hint` 自身仍算出 nowrap，字被压成 432px 一行塞进 204px。
- 改法：把 `white-space: normal` 写在 `.dt-filter-hint` 自己身上（类选择器压过 `*`）；`code` 补 `nowrap` 防表达式断行；面板宽 212→240，实测提示 2 行、scrollW==clientW==232、三个 code 右边界 502 < 面板 528，亮/暗一致。
- 排查手法：CDP `CSS.getMatchedStylesForNode` 直接列出命中规则，比遍历 `document.styleSheets` 快（后者对嵌套 CSS 的 `&` 选择器 `matches()` 会抛错漏掉）。
