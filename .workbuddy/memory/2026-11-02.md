## Univer 暗黑模式画布白底修复
- 现象：暗黑模式下 Univer 整张表体白底（含列头与数据区），周边 UI 已暗。根因是 `buildUniverTheme(true)` 拿亮色 `defaultTheme` 手搓灰阶当暗色用——场景主背景那一档没被暗化，画布仍白。
- 修复：暗色改用官方 `darkBlueTheme`（`@univerjs/presets` 经 `export *` 透传可 import）为基底，只把 `gray.0/50/100/200` 微调成中性深灰与另两套一致，叠品牌 `primary` 与查找高亮；亮色保持 `defaultTheme` + 品牌色。`useEntrySheet.ts`。
- 附修两 bug：① `highlight.background[i].color` 之前填了十六进制（应为主题键路径 `"orange.400"/"orange.600"`），查找高亮失效；② `writeHeader` 表头底色硬编码 `#f1f4fb`，暗黑不变 → 改为跟随站点的 `html.dark`，并在页面 `syncTheme` 主题切换时重下发表头。
- 校验：eslint/vue-tsc/stylelint/check:nav/check:components 全绿。Univer 画布本机 headless 0×0 渲不出，视觉效果需用户本机确认。

## 关于"点列头开配置抽屉"
- 三套都支持且都用同一 `ColumnDrawer`：vxe 原生 `header-cell-click`；VTable 点列头弹抽屉；Univer 无原生列头点击回调 → 用「点列标整列选中」A1 信号等价实现。
- **修正**：整列选中的 A1 实测是简写 `E:E`，不是 `E1:E20000`。旧正则 `/^([A-Z]+)1:\1(\d+)$/` 永不命中 → 抽屉打不开（用户说的"univer 好像还不支持"）。改为同时认 `^([A-Z]+):\1$` 与全量（需行数到底），列索引按字母 reduce 自算。CDP 实测：点 B 列 → 抽屉「列设置 · 年龄」宽 520 正常弹出。

## 右键菜单"字小了框还巨大"的真正根因（本仓特有）
- CDP 实测 .univer-popup 面板：菜单项高 68px、面板宽 277px、容器 gap 19.5px，但 font-size 12.5px —— 字号被压住、rem 间距没压住。
- 根因：`assets/css/common.less` 的大屏模板 `:root { font-size: calc(100vh / 10.8) }` 把根字号顶到 **78.1481px**，Univer 的 Tailwind 全用 rem，所有 gap/padding/min-w/size 被放大 ~4.88 倍（`gap-1` = 0.25rem = 19.537px，精确吻合）。rem 恒相对根 html，压容器 font-size 无效。
- 修法：进页 `documentElement.classList.add('univer-normal-rem')` + `html.univer-normal-rem{font-size:16px}`，离开移除。实测根字号 16px 后：菜单 277×828 → **184×301**，项高 68→24px，gap 19.5→4px，位置对准鼠标；侧边栏/表格布局无变化（本页与外壳全 px，源码 rem 仅 6 处且是 demo 页）。
- 另一处纠错：真实弹层是 `<section class="univer-popup univer-fixed">` 挂 body 下，`.univer-popup` 类是有效的；`#univer-popup-portal-*` 是**空容器（0 子节点）**，此前按它写的选择器全是死代码，已清掉。
- 方法教训：这类问题必须起 dev server + CDP 抓真实 DOM/computed style，纯看源码会反复猜错（前一版两次"修复"都是死代码）。

## 暗黑模式表格仍白底 —— 真正根因（反色机制，前面两次都改反了）
- 用户二次反馈"暗黑下表格还是白"，这次起 dev server + CDP 实测坐实：`setDark` 确实执行成功（日志 `gray0=#16191f`），但画布是 `rgb(242,243,245)`。
- 根因：`engine-render` 的 `CanvasColorService.getRenderColor()`：先按主题键解析真实色 → **若 `themeService.darkMode` 为真则用反色矩阵翻转**。所以"暗色主题 + darkMode 开"= 暗色再被翻成亮色 → 白画布。之前两版（手搓灰阶、darkBlueTheme 基底）都是同一个错。
- CDP 三组实测：亮主题+开关开 → lum 207（暗✅）；暗主题+开关开 → 243（白❌）；暗主题+开关关 → 243（白❌）。结论：**主题只做亮色基调，明暗全交给 toggleDarkMode**。
- 连带修正：`writeHeader` 原来按 `html.dark` 写 `#20242c`，会被反转成亮色 → 改为恒写 `HEADER_BG_LIGHT='#f1f4fb'`（提到 schema.ts 常量）。移除 `darkBlueTheme`/`BRAND_PRIMARY_DARK`/`GRAY_DARK_OVERRIDE`。
- 验证：截图确认暗黑下数据区/表头/列标均为深色、文字可读；切回亮色正常。五项校验全绿。

## 验证环境配方（本机可复现，比"纯看源码"可靠得多）
- 临时 `vite.probe.config.ts`：`cacheDir` 指**全新**目录名（每次换名，否则 re-optimize 删旧 deps 撞沙箱删除守卫）；`optimizeDeps.include` **必须写全** Univer 全部 preset + locales + xlsx + element-plus，否则运行时会二次预构建再撞守卫；缺依赖用 alias 指 stub（`mitt` 要 callable 默认导出）；**`resolve.alias` 要带 `'@': src`**，覆盖式配置会丢掉原 alias 导致 `@/components/...` 500。
- 服务只监听 `[::1]:19709`，脚本要用 `http://localhost:19709`（127.0.0.1 连不上）。
- 进页面：点 `span.ai-item__label`（文案 "Univer BI 数据录入"），SPA 内部跳转；直接 Page.navigate 到路由会拿到空 shell。
- 切暗：`document.documentElement.classList.add('dark')` 即可（页面 MutationObserver → syncTheme）。
