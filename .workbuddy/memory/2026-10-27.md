## 晚间：git 同步（网络出口复测）

- 结果：`git merge --ff-only origin/main` 快进 4 个提交（ec4fc89a → fada2316），本地与 origin/main 完全同步，工作区干净、无待推送提交。
- **新发现（修正旧结论）**：`git fetch` 走沙箱代理仍是 `502`，直连 6 次全超时，**但有一次在“沙箱绕过”下成功了一次**，ref 更新了、对象也下载到了本地。→ 下次遇到 GitHub 443 不通时，先 `git fetch` 碰运气，然后**直接 `git merge --ff-only origin/main` 消化本地已有的 origin ref**，别急着下“网络不通”的结论（fetch 失败也可能已留下可用的 ref，用 `git rev-list --left-right --count origin/main...HEAD` 判断）。
- **SSH 方案**：`github.com:22` **可达**（`ssh-keyscan` 拿得到主机密钥），但 `~/.ssh/id_rsa` 未授权到 GitHub 账号 → `Permission denied (publickey)`。要用 SSH 通道，需用户把 `~/.ssh/id_rsa.pub` 加到 GitHub SSH Keys。

### 经验
- 本仓库 `collect` 的包名是 `vue-plugins-components-collect`，`pnpm --filter collect` 匹配不到。
- `pnpm install` 全量在本工作区极慢（8 个项目，30min+）；只改锁文件时用 `--lockfile-only`（15s 级），只想装某个项目用 `--filter <包名>`。
- lint-staged 会 `git stash create` 备份 + 失败时 `git reset`，reflog 里能看到 `reset: moving to HEAD`；它留下的 `lint-staged automatic backup` stash 若被 re-apply，会把已修好的文件倒退成旧版。
