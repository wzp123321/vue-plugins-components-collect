# UI 测试用例自动执行

## 何时使用

- 用户提供测试用例库 `.xlsx` 并要求执行、验证实施效果。
- 用户说「执行 1 级用例」「只执行 1」「按级别跑」——级别取自用例库 `级别` 列，等于 `1` 即 1 级。
- 用户要求重跑回归、按用例编号跑指定批次、或查看上次执行结果。

## 唯一真相源

先读 `D:/workspace/company/test-workspace/INDEX.md`。环境地址、组织、带参 URL、用例库路径、用例→代码映射、待补清单都在其中，**不要重新探查一遍**。

| 文件 | 用途 |
|---|---|
| `credentials.local.env` | 账密。执行时读取，禁止写入 skill、记忆或对话 |
| `auth-group.json` | 「集团总部」组织的浏览器登录态，执行前 `state-load` 复用 |
| `cases-*.json` | 各用例库的机读副本 |
| `runs/<批次>/RESULT.md` | 每次执行的结论与观察证据 |

## 启动自检（Pre-flight Check）

开跑前必须先过这一关：**任一项不通过则一次性列出缺失项并停止，不打开浏览器、不解析、不执行**；全部通过才进入「执行流程」。目的是把"依赖缺失 / 环境不可达 / scope 不齐 / 素材与授权未备"在启动前集中暴露。

1. **依赖文件存在性**（参照上文「唯一真相源」表，不重复罗列）：
   - `INDEX.md`、`credentials.local.env`、`auth-group.json` 三者在 `D:/workspace/company/test-workspace/` 下存在；
   - 解析脚本存在：`C:/Users/wanzh/.workbuddy/skills/ui-case-runner/scripts/parse_cases.py`。
2. **用例库存在性**：用户提供的 `.xlsx` 路径，或 `INDEX.md` 指明的权威用例库路径，文件存在且可读。
3. **环境可达性**：对 `INDEX.md`「环境」节中的目标地址做一次轻量 HTTP 探测（期望 2xx/3xx 或登录页响应）；不可达直接标 `BLOCKED` 并停止，不进入浏览器步骤。
4. **INDEX.md 明文校验**：`.md` 可能被透明加密，读取前确认非密文（出现 `E-SafeNet` 标记即密文）；若为密文，先解密再继续，禁止拿密文当真相源。
5. **scope 三要素**：用例库 + 级别 + 模块/页面 是否齐全且用户已确认（门控逻辑见「执行流程」第 3 步，此处仅做存在性确认）。
6. **全量用例依赖盘点**：在已有页面地址等前置条件之上，对 scope 内**每一条**用例过一遍，确认是否需补素材、素材放在哪、要哪些业务数据与写动作授权（规则见「前置依赖与素材盘点」）。**清单未经用户确认不得开始执行**。

自检输出格式：通过则输出「依赖清单 + 授权清单」供用户一次性确认，确认后才进入执行；不通过则打印「缺失项清单」后停止，等用户补齐再跑。

## 执行流程

1. **读台账** `INDEX.md`，确认目标环境、当前权威用例库、上批次结论。
2. **解析用例库**：`python "C:/Users/wanzh/.workbuddy/skills/ui-case-runner/scripts/parse_cases.py" <xlsx路径> > cases-<批次>.json`。脚本只用标准库（本机无 openpyxl / pandas），JSON 走 stdout，摘要走 stderr；脚本绝对路径已写死，执行时工作目录不必是 skill 目录。
3. **锁定范围（硬门控）**：scope 三要素 = 用例库 + 级别 + 模块/页面，三者必须齐全且经用户确认，**确认前不得打开浏览器**。用户说「只执行 1」即 `级别 == '1'`；用户限定「本次只跑数据门户 2 级」时以该口径为准，不跨库、不跨级、不跨模块。输出总数、模块分布、key 清单供确认；缺任一要素只问一次，不按默认补齐、不擅自扩大到相邻级别或其他库。
4. **建批次目录** `runs/<YYYY-MM-DD>-<批次名>/`；把自检确认的素材路径、缺失项、授权范围写进 `RESULT.md`「用例范围」，不另建清单文件。
5. **执行**：按「浏览器操作铁律」逐条跑，**每条用例每个步骤落一条 DOM 证据或阻塞原因**（见「判定口径」）；找不到入口时先走「代码检索归因」，不直接标未执行。
6. **判定并落盘** `RESULT.md`：把代码归因结论回填证据列，更新 `INDEX.md` 的执行证据与待补清单，追加当日工作日志。
7. **数据台账**：把本批次自造对象登记到 `RESULT.md`「本次产生的数据」表；**自造数据允许保留、不强制复位**，可作为后续批次基线（见「安全红线」）。仅当用户明确要求清理时才执行删除，不静默清理。
8. **交付**：`present_files` 展示 `RESULT.md` 与 `INDEX.md`，正文给结论表 + 待拍板事项。

## 前置依赖与素材盘点

在启动自检第 6 项执行，覆盖 scope 内**全部**用例，不抽样。逐条读 `前置条件` / `步骤` / `预期结果`（用例库 `数据` 列常为空，依赖写在 `前置条件` 里），按四类归集：

| 类别 | 识别信号 | 处置 |
|---|---|---|
| 素材 | 图片 / 视频 / Logo / 上传 / 附件 / 格式 / 大小限制 | 列出**文件名 + 本机绝对路径**；能用标准库生成的（PNG/JPEG、超尺寸图、文本类）直接生成到素材目录，不能生成的列明请用户提供并给出目标路径 |
| 场景基线 | 「画布已存在多个组件」「已添加明细表并选择指标」「同一报表中存在多个图表」 | 在自造对象上先搭好基线再跑，不拿他人数据当基线 |
| 业务数据 | 院区点位 / 跳转规则 / 已发布大屏清单 / 指标与事实清单 | 需要环境数据或只读接口，开跑前一次问清；拿不到整组标 `BLOCKED` |
| 动作授权 | 新增 / 编辑 / 删除 / 发布 / 下线 / 更新 / 保存 / 确定 | 汇成一次性授权清单，见「安全红线」 |

- 素材统一放 `D:/workspace/company/test-workspace/assets/<批次>/`，命名 `自动化_<日期>_<用例key>_<用途>.<ext>`；清单里必须写**绝对路径**，上传时按该路径取文件。
- 盘点结果按「可直接生成 / 需用户提供」两组输出，一次问清；未确认前不打开浏览器、不开始执行。
- 盘点结论（素材路径、缺失项、授权范围）写进 `RESULT.md`「用例范围」。

## 浏览器操作铁律

用 `playwright-cli`。违反以下任一条会白跑：

- **每条 Bash 命令自包含，但不要一条用例重开一次浏览器**：一次 Bash 调用内串 `close-all` → `open --persistent` → `state-load <auth-group.json>` → 多条短 `run-code`。会话不跨 Bash 调用，单独发 `run-code` 会报 `Browser 'default' is not open`；反复 `close-all` 会重建登录态、拖慢批次。
- **登录后组织选「集团总部」**。选「测试机构1」时工作台只有「能源管理」，看不到目标磁贴。
- **URL 参数规则以 `INDEX.md`「环境」节为唯一真相源**，此处不复制清单。执行前按台账拼带参 URL；冷启动直连缺参返回 46020015。同一会话内由磁贴 /「配置」按钮新开的标签页可不带 query（实例上下文由会话注入），会话一旦重建必须回到带参直连。
- **磁贴与「配置」按钮都以新标签页打开**：用 `page.context().pages()` 取最后一个页面。
- **无文字图标按钮用坐标点击**：数据门户配置页「大屏目录」右上角的「+」是 `svg.teicon--icon-plus`，无 title / aria-label。用 `evaluate` 找「大屏目录」文本节点的父元素 → 取其中最后一个 svg/button 的 `getBoundingClientRect()` → `page.mouse.click(x, y)`。菜单项是 `.te-dropdown-menu__item`，含「新增分组」「新增内容」。
- **悬浮类按钮先 hover**：卡片操作 `.card-action-button`、分组「┄」`svg.teicon--icon-more-filled` 都在 hover 后才渲染，取坐标前先 `hover()` 宿主元素；下拉菜单偶发不展开时重试点一次。
- **树形下拉先展开再读**：`.te-tree-select__popper` 初次只渲染根节点，点 `.te-tree-node__expand-icon` 展开后再取节点文本；可选项用 `[aria-disabled="false"]` 判定，`aria-disabled="true"` 是分组节点不可选（104988 / 105008）。嵌套子分组需二次展开。
- **预览内容在 iframe / 新标签页里**：新标签页取法同上；再 `frameLocator` 进 iframe 取渲染文本，不要在外层 `innerText` 里找（105034 / 105020 / 105003）。
- **单条 `run-code` 保持短**：一次只做 1 个页面 + 1 组操作。多个 `goto` 叠加拖拽容易超时被 SIGTERM；拆成多次调用。
- **拖拽组件用鼠标坐标**：`boundingBox()` 取源与目标 → `mouse.move/down/move(steps:10)/up`。`dragTo()` 在该编辑器上不可靠。
- **读表单值用 `inputValue()` / `evaluate` 取 `value`**，`innerText` 不含 input 的 value。
- **截图**：`playwright-cli screenshot --filename=<相对名>`，用绝对路径会导致超时。
- **失败先看 console**：`.playwright-cli/console-*.log` 里的 401 / 400 常是登录态或参数缺失的线索。

## 判定口径

- 只写**实际观察到的 DOM 值 / 文本 / 属性**作为证据，不臆断、不补全。
- **逐步证据（硬约束）**：用例库 `步骤` 里每个编号（`【1】【2】…`）都必须落一条 DOM 证据，或写明阻塞原因；证据列按 `【1】…【2】…` 对齐步骤编号。**禁止把「只读浏览了面板 / 看到了配置项」判为通过**——那只是入口存在，不是步骤结果。
- 未走完的步骤强制标 `N/M 步通过`（写进证据列，判定值仍用四档），写明止步原因（缺素材 / 缺数据 / 未授权 / 入口未找到 / 代码结论），不省略、不笼统写「未验」。
- 「默认值」类用例必须在**新建空白对象**上验证；已有对象的保存值不能当默认值基准。
- 用例文案与界面文案不一致 → 标「待确认」，说明是文案过时还是缺陷待定，不直接判失败。
- 前置条件不满足（缺点位规则、缺多页面大屏、缺素材）→ 标「未执行」并写明缺什么，不跳过也不隐瞒；若属可自行生成的素材或可搭建的场景基线，先补再跑，不得直接标未执行。
- 写操作按「安全红线」的批次授权清单执行；未列入授权的动作以「取消」收尾。

## 代码检索归因

遇到「入口 / 字段未找到」或标 `待确认` 的项，**不得直接停手**，先做代码检索再判：

1. **定位源码根**：唯一真相源是 `INDEX.md`「目标版本」指定的那份 `.code-workspace`，路径不在本文件复制。
   - 工作区内可能同时存在其他版本的多份 `.code-workspace`；**只认台账指定版本那一份**，禁止按文件名、目录扫描结果或修改时间自行挑选。
   - 用 `utf-8-sig` 读 `folders[]`（文件带 BOM）；`path` 相对 `.code-workspace` 所在目录归一成绝对路径。工作区自身条目是工具仓、单仓条目无版本后缀，按原路径取，不套版本规则。
   - 工程清单只从 `.code-workspace` 取；`workspace.local.env` 的仓库名清单是环境搭建配置，不作为归因依据。
   - 逐仓 `git -C <绝对路径> branch --show-current` 核对与目标版本一致；**路径名带版本号不等于 checkout 版本**，不一致时该仓标为不可归因并写明实测分支，不拿它的代码下结论。
   - 先用 `INDEX.md`「用例 → 代码映射」把用例模块收敛到具体目录；热点表未覆盖的模块再按上面的清单定位到工程根。两处都不复制工程路径清单。
2. **grep 前判密文**：`.md` / `.java` 等可能被透明加密，含 `E-SafeNet` 标记即密文，改用 `git show` 或白名单读取器；禁止把密文导致的检索无结果当作「未实现」。
3. 用组件名、界面文案、字段名、路由名 grep 源码（`*.vue` / `*.ts` / router 配置），确认功能是否有实现、入口挂在哪。
4. 三选一给结论，写进证据列：
   - **未实现**：源码里无该组件 / 字段 / 菜单项 → 疑似缺陷或规划中未实现。
   - **入口隐藏**：源码有实现，但需特定条件（选中态、hover、权限、tab 切换）才渲染 → 按条件重试，成功则改判通过。
   - **用例过时**：源码里字段 / 文案与用例不同名 → 标「待确认」并附源码里的实际名称。
5. 结论要带**文件路径 + 命中关键字 / 行号**，可复核；检索不到也要写明查过哪些路径，不能只写「未找到入口」。

## 安全红线

**授权模型**

- 新增 / 编辑 / 删除 / 发布 / 下线 / 更新 / 保存等写动作，开跑前汇成**一次性授权清单**（见「前置依赖与素材盘点」）向用户确认；确认后按清单执行，不再逐条停下来问。
- **编辑 / 删除 / 发布 / 下线只允许作用于本自动化用例新建的数据**（`自动化_<日期>_*` 前缀），不影响环境里原有数据；对原有对象一律禁止这些动作，共享环境存在他人「勿动」大屏。发布 / 下线只改变自造对象自身的可见性，不动原有对象的发布状态。
- **执行用例允许新增数据，且不要求复位**：自造对象可保留，作为后续批次的可复用基线；`RESULT.md`「本次产生的数据」表登记对象名与用途。仅当用户明确要求清理时才执行删除，删除仍走上面的授权清单。
- **发布 / 下线与其他写动作同口径**：列入一次性授权清单，确认后按清单执行；发布状态可保留。

**不可越界**

- 造数据统一用 `自动化_<日期>_*` 前缀命名。
- 账密只从 `credentials.local.env` 读取，不回显、不落记忆、不进 git。

## 结果表格式

`RESULT.md` 必含：用例范围（库路径、级别分布、总数、**素材路径、授权范围**）、入口打通结论（组织、带参 URL）、**一张覆盖全部用例的结果表**、本次产生的数据表、数据安全声明。

### 单一结果表

- **本批次每一条用例占且仅占一行，全部放进同一张表**。跨用例信息只用统计数字或正文段落表述，不在别处重复列用例。
- 固定列：`用例 | 标题 | 操作步骤 | 预期结果 | 实际结果 | 观察证据 / 未执行原因`，按用例编号升序。
- 「操作步骤」「预期结果」**取自用例库原文、完整展示**，不改写、不摘要；原文换行转成 `<br>` 保留 `【1】【2】` 分步编号，单元格内 `|` 转义为 `\|`，避免撑破表格。
- 「实际结果」列是判定值，只用四种：`通过` / `部分通过` / `待确认` / `未执行`。N/M 步、未验步骤、口径差异、实际观察到的 DOM 证据都写进「观察证据 / 未执行原因」列，不新增判定值。
- 证据列按步骤编号 `【1】…【2】…` 逐条记录，逐步证据与 N/M 步写法见「判定口径」；疑似缺陷加 `【疑似缺陷】` 前缀，代码归因结论附源码路径；未执行行必须写明缺什么（业务数据 / 素材 / 授权 / 入口），不能只写「未执行」。
- 落盘前用脚本核对：表内 key 集合 == 本批次 scope 的 key 集合（数量一致、无重复、无遗漏）、每行 6 列、操作步骤与预期结果两列非空且与用例库原文一致、证据列覆盖每条用例的全部步骤编号或写明阻塞原因，核对通过再交付。
