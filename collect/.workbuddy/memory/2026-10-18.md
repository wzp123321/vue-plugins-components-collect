## 全模块代码风格统一：全部 ref + 箭头函数（threejs-china-3d-map）
- 用户要求：threejs-china-3d-map 下响应式一律 `ref`（禁 `reactive`）、所有函数一律箭头函数（`const f = () => {}`）。共改造 ~123 处 `function` 声明 + 1 处 `reactive`。
- `threejs-china-3d-map.vue`：`const cfg = reactive({...})` 拆成 6 个独立 ref（showColumn/columnColor/showFlyline/flylineColor/flylineSpeed/dragMode），模板 `cfg.x` 全改为裸变量名；`dragMode` 补 `ref<'pan' | 'rotate'>('pan')`。
- 工具式批量改造要点：**不能用 prettier**（`.prettierrc` `endOfLine: lf`，但本目录工作副本全是 CRLF，跑 prettier 会把整文件换行符翻掉、diff 爆炸）；Python 脚本必须 `open(newline='')` 读写以保 CRLF。
- 自写脚本的坑：签名扫描时**不能把 `{` 计入通用括号栈**（返回类型里的对象字面量 `{ hub: [...] } | null` 会被误判成函数体起点）→ 只有 `( [` 进栈，`{` 在栈顶为空时才是 body 起点。改完务必 grep `: =>` / `): =>` 找错位产物。
- 转换后语法在 TS5.3 下没问题（含对象返回类型/多行参数列表），旧记忆里「这类写法解析失败」那条已作废。
- 校验：`vue-tsc --noEmit` 过滤 china-3d 零报错；另写脚本扫「定义前调用」（TDZ 风险）确认无命中。
- 未跟踪文件（MapSearchBox.vue / utils/anchor.ts）没有 git 历史可回滚，**改前先备份**再跑批量脚本。
