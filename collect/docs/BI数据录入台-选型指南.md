# BI 数据录入台 —— 选型指南

> 接到「做个表格录入页」的需求时，先按业务特征在这里定位：选哪套插件、哪部分必须自己写。  
> 三套实现并列维护：**vxe-table**、**@visactor/vtable**、**Univer**。功能面按同一份需求清单对齐，没有主次之分。  
> 功能状态以**代码**为准，不以官网宣传或早期文档为准。怎么实现、坑在哪，见 `BI数据录入台-实现细节.md`。

## 一、结论：选谁看业务特征

三套是**并列的，不是主备关系**。新需求进来三套都要加，能力面按同一份清单对齐；某套架构上做不到的，在第三章标 `✕`，需求评审时提出，不靠「降级为技术验证页」绕过。

| 业务特征 | 选 | 原因 |
| --- | --- | --- |
| 列结构随业务变、要嵌业务组件、要能 e2e 断言 | **vxe** | DOM 结构，改列只改数组 |
| 十万行级、以看为主、单元格样式驱动 | **VTable** | Canvas 最省内存 |
| 要公式、多 sheet、导入导出保真 | **Univer** | 唯一有完整表格语义 |

三套自研占比相当（vxe 75% / VTable 74% / Univer 46%）—— 工程量 70% 以上不在渲染层，而在校验、列模型、查询、IO、撤销、模板。**换插件不等于换工作量**，选型只看业务特征和你愿不愿付某个库的改造成本。

落地四条：① 新录入台从最贴合业务特征的一套复制，列定义/校验/IO/撤销骨架三套等价，可直接搬；② 同一需求三套同步加，否则选型表的 `✕`/`◇` 会随时间失真；③ 外观由 `src/assets/style/bi-entry.less` 统一（`--bi-*` + `.bi-*`），新页面挂类即可；④ 做不到的（第三章 `✕`）在评审时当场提出。

## 二、五维对比总览

下面是把「能不能用、好不好做、好不好扩、好不好换」压成一张表。**功能对比与能否实现的全量明细在第三章矩阵**，这里只给结论性评级。

| 维度 | vxe-table | @visactor/vtable | Univer |
| --- | --- | --- | --- |
| **功能覆盖（能否实现）** | 最广，仅「导出保真」`✕` | 4 项 `✕`（内嵌组件、e2e、无障碍、导出保真） | 5 项 `✕`（多级表头、导出保真等），但原生语义最全 |
| **实现难易（从零搭一套）** | **易**：DOM，列即数组；组件/编辑器/校验即插槽式扩展，无 Canvas 学习成本 | **中**：列模型数据驱动（加减列便宜），但右键/错误气泡/悬停提示/主题色都要自绘 Canvas 浮层，内置编辑器仅 4 种 | **中高**：原生能力最多，但定制要吃它的命令/插件体系，列变更即整表重写，React 硬依赖，学习曲线陡 |
| **可拓展性** | **高**：单元格可插任意 Vue 组件；渲染器/编辑器/校验器皆可替换；新增能力多在业务层，不碰内核 | **中**：列配置是纯数据，加减列便宜；但单元格不能嵌组件、自定义浮层要 Canvas 自绘，主题要读计算样式转 `TableTheme` | **中低**：原生能力全，但一切走内核命令与整表重写，扩展要懂插件体系；Pro 能力（透视/图表/保真导入导出）是商业授权，迁出后要自补 |
| **可替换性** | **高**：列定义为数组、渲染层最薄、业务与 DOM 解耦（slot 而非入侵）；迁到另一 DOM 表格成本最低 | **中**：渲染层厚（Canvas API），但列模型数据驱动；迁走主要重写单元格渲染与事件绑定 | **低**：表格语义深嵌业务（选区即 A1、列变即重写），迁移≈重写数据层；且 Pro 能力是商业授权 |
| **自研占比 / 改造成本** | 75% | 74% | 46% |
| **一句话定位** | 改起来最便宜、最不锁死 | 大表性能主场，定制靠 Canvas 自绘 | 原生表格语义最多，但要付内核学习税 |

> 可替换性的前提：业务层（列模型、校验、IO、撤销、跨列规则）已收口到 `src/utils/bi-entry.ts` 与三套各自的 hooks，与渲染层解耦。**换插件 = 重写渲染/编辑器绑定层，规则引擎不动**。详见第五章。

## 三、范围与规则口径

| 项 | 口径 |
| --- | --- |
| 列类型 | **仅 4 种：文本 / 数字 / 下拉 / 日期**。布尔、附件、公式列、富文本列均不做 |
| 分页 | **不做**，大表一律虚拟滚动（已实现的分页视图仅作代码参考） |
| 协作 | 不做实时协同、评论、@提醒 |
| 端 | 仅桌面浏览器，不做移动端适配 |

四类字段的标准规则（写新页面照此实现）：

| 类型 | 格式 | 范围 | 其他 |
| --- | --- | --- | --- |
| **文本** | 正则 `pattern` + 自定义文案 | 长度 `minLen ~ maxLen` | 整列唯一 |
| **数字** | 必须是数值 | 闭区间 `min ~ max` | 整数、整列唯一 |
| **下拉** | 必须是选项之一 | — | 选项不可自由输入 |
| **日期** | `YYYY-MM-DD` 且必须真实存在 | 仅跨列比较 | 显示格式可配，存储恒定 |

- 四种类型都支持**必填**；空值只判必填，不跑其他规则。
- **跨列规则**四种：`≥` / `≤` / `=` / `参照列非空时必填`。文本与日期按字符串比（ISO 字典序即时间序），数字按数值比。
- **唯一性**只比非空值，空值不参与。
- **存储与显示分离**：日期存 `YYYY-MM-DD`，`dateFormat` 只影响呈现。

## 五、可拓展性

按「加新能力要动多少、动哪层」排序：

- **vxe（高）**：真实 DOM，单元格可插任意 Vue 组件（`slot` / `cellRender`）；渲染器、编辑器、校验器都是插槽式扩展，换一个不影响其它；新增能力多在业务层，不碰内核。定制全靠 DOM/CSS，团队零 Canvas 学习成本。
- **VTable（中）**：列配置是纯数据，加减列便宜；但单元格**不能嵌组件**，一切自定义 UI（右键菜单、错误气泡、悬停提示、主题色）都要自绘 Canvas 浮层，成本高；内置编辑器只有 4 种（无 NumberEditor）；主题要 `getComputedStyle` 读 `--bi-*` 转 `TableTheme`。
- **Univer（中低）**：原生表格语义最全（公式/多 sheet/样式），但一切走内核命令与整表重写；扩展要懂它的插件/命令体系，列一变动全链路重下发；Pro 能力（透视表、图表、`exchange` 保真导入导出、打印 PDF、协作）是商业授权，迁出后这些能力要自己补。

## 六、可替换性

**前提**：业务层（列模型、校验、IO、撤销、跨列规则）已收口到 `src/utils/bi-entry.ts` + 三套各自的 hooks，与渲染层解耦。所以「换插件」= 重写**渲染/编辑器绑定层**，规则引擎不动。按「迁出时要扔掉多少」排序：

- **vxe（高）**：列定义为数组、渲染层最薄、业务代码与 DOM 解耦（`slot` 而非入侵式）；迁到另一 DOM 表格成本最低——基本只换模板与编辑器绑定。
- **VTable（中）**：渲染层厚（Canvas API），但列模型数据驱动；迁走主要重写单元格渲染与事件绑定，编辑器可复用 VTable 内置。
- **Univer（低）**：表格语义深嵌业务（选区即 A1、列变即整表重写），迁移≈重写数据层；且 Pro 能力是商业授权，迁出后这些能力要自己补。若已重度依赖公式/多 sheet，`✕` 项会反向锁死选型。

> 实际结论：本仓库同时维护三套，正是把「渲染层可替换」当硬约束。新业务优先选 vxe（最不锁死）；只有数据量或原生语义（公式/多 sheet）成为硬需求时才上 VTable / Univer。

## 八、样式与主题一致性

三套共用同一套色板 `--bi-*`（`assets/style/bi-entry.less`）：冷灰底 + 白面板，层次靠 1px 细线与灰阶明度，不靠渐变、彩色投影、大圆角；主色只出现在当前位置/关键动作。

- **来源**：项目内部自定（「数据平台克制风格」），未参照有数 BI 或其它具体产品的设计令牌——这样可保持三套观感一致且无第三方授权风险。要换成某产品风格需提供其色板令牌。
- **三套如何吃同一套色板**：
  - vxe：原生 CSS 变量，经 `:deep()` 覆写 `.vxe-*` 取值；
  - VTable：建表时 `getComputedStyle` 读 `--bi-*` 转 `TableTheme`，行悬停/选区/滚动条/排序图标色都从 `--bi-*` 取；
  - Univer：原先只 `toggleDarkMode`，画布仍走内置默认色；现已注册品牌主题（`{...defaultTheme, gray, primary, highlight}` 由 `--bi-*` 映射），网格线/表头底/选区/查找高亮与其余两套对齐。
- **暗黑/白天**：三套都跟随站点 `html.dark` 响应式切换——vxe 走 CSS，VTable 在 `isDark` 变更时 `rebuild()`，Univer 用 `MutationObserver` 监听 `html.dark` 并整体 `setTheme`。悬停（行高亮/表头图标显隐）与选区高亮三套表现一致。
