# 飞线与地图背景图 —— 工时估算

> 配套使用：《效果与实现全景》（看有哪些效果）、《需求确认说明书》（看要确认什么）。
> 本文回答一个问题：**这套东西，几个人天。**

---

## 〇、先说清三个前提，否则数字会被误用

| 前提 | 说明 |
|---|---|
| **单位** | 1 人天 = 6 小时有效编码时间（不是 8 小时）。一个人连续做，不含等待、开会、环境搭建 |
| **口径** | 全文默认「**在已有 three.js 地图页面上做增量**」（本项目现状）。从零做的基线单列在第四节 |
| **不含** | 需求沟通、设计出图、素材采购、部署上线、跨部门联调。这些按项目另算 |

**一条经验系数**：真实项目里，**「把效果做出来」只占 55%~65%**，剩下是适配、联调、改。所以后面每个套餐我都给「实现天数」和「交付天数」两个数。

---

## 一、飞线：逐项工时（增量口径）

### 1.1 纯调参（L1 级，不新增结构）

| 需求说法 | 工作量 | 说明 |
|---|---|---|
| 换个颜色 / 亮度 | 0.2 人天 | 改一个变量，连测都不用量 |
| 调快 / 调慢 / 调弧高 | 0.2 人天 | 同上 |
| 调整线宽、拖尾长度、头部大小 | 0.5 人天 | 要试几档找手感，得盯着看 |
| 开关某一层（飞线 / 底板 / 星空） | 0.2 人天 | 已有开关就是 0 |
| **调参小计** | **0.5~1 人天** | |

### 1.2 换效果（L2 级，新增一层或换实现）

| 效果 | 实现 | 交付 | 备注 |
|---|---|---|---|
| F04 双向对开 | 0.5 | 0.5 | 复制一条反向，几乎无风险 |
| F09 端点涟漪 | 0.5 | 0.7 | 三个 Ring 错相位；别进 bloom 层 |
| F11 逐段生长进场 | 0.5 | 0.8 | 要和层级切换的下钻时机对齐 |
| F13 多层拖影 | 0.5 | 0.7 | 线数 ×3，要盯帧率 |
| F03 流动虚线（另做一套材质） | 1.0 | 1.5 | 要处理 `computeLineDistances`，和现成 ribbon 并存 |
| F07 渐变描边（已有） | — | — | 本项目已完成 |
| F12 遮挡关系切换 | 0.3 | 0.4 | 改一个 `depthTest` + 排序 |
| **效果小计（挑 2~3 个）** | **1.5~3** | **2~4** | |

### 1.3 重活（L3 级，换实现方式）

| 效果 | 实现 | 交付 | 为什么贵 |
|---|---|---|---|
| F05 管道流光 | 2.5 | 3.5 | 要引入 Tube + 灯光 + 贴图滚动；线一多就崩，得先做数量上限策略 |
| F06 粒子飞线 | 3.0 | 4.0 | 要写 shader、做曲线查表纹理、调点大小与 pixelRatio |
| F10 数据驱动粗细/颜色 | 1.5 | 2.5 | 效果不难，难在**数据结构要改**（每条线带 value/status）+ 色板可配置 |
| 千条级性能优化 | 2.0 | 3.0 | 合并 geometry / instancing / 分帧更新，要配性能探针 |
| F14 球面大圆弧 | 3.0 | 4.0 | 换地球底座，等于换半个项目 |
| **重活小计（任选其一）** | **1.5~3** | **2.5~4** | |

### 1.4 交互（最容易被漏，但产品一定会提）

| 项 | 实现 | 交付 |
|---|---|---|
| hover 高亮某条线 | 0.5 | 0.7 |
| 点击某条线弹详情 | 1.0 | 1.5 |
| 点击后飞线跟随筛选变化 | 0.5 | 1.0 |
| **交互小计** | **0.5~2** | **0.7~3** |

## 三、跨领域的固定成本（每次都要算，不能省）

| 项 | 人天 | 说明 |
|---|---|---|
| 数据接入（接口 + 字段 + 真实坐标） | 1.0~2.0 | 飞线端点从「写死的 13 个城市」换成接口数据，工量取决于对方接口质量 |
| 多分辨率适配（1920 / 2560 / 3840 / 超宽） | 1.0~2.0 | 每加一个分辨率就要重看一遍面板、线宽、背景裁切 |
| 性能调优到 50 FPS 以上 | 0.5~1.5 | 看条数和后处理开销 |
| 现场联调（投屏偏色、网络、机器差异） | 1.0 | 外勤另算；这一步几乎从不缺席 |
| 验收返工预备金 | **+20%** | 不是可选项。行业惯例，把它写进报价 |

## 四、从零做的基线（换项目时用这个，不叠加前面的数）

| 模块 | 人天 |
|---|---|
| 三维地图底座（GeoJSON 加载、投影、挤出、层级下钻、相机、控制器） | 6~9 |
| 后处理链（EffectComposer + bloom，含 alpha 坑） | 1.5 |
| 飞线（ribbon + 动画 + 像素下限 + 头部光点） | 3 |
| 背景（CSS 底图 + 场景底板 + 星空 + 双主题） | 2 |
| 控制面板 + 图层开关 + 主题切换 | 2~3 |
| 数据接入 | 1~2 |
| 适配 + 联调 + 返工 | 3~4 |
| **合计** | **18~25 人天** |

> 换句话说：本项目已经省掉的，是一个「18~25 人天」的地基。这就是为什么在现有页面上加效果，报价能压到几天。

## 六、报价三条纪律

1. **不报单点价。**
   「加个飞线多少钱」这个问题没有答案。必须让对方先选套餐，再报一个区间。否则后期每加一个效果都要重新谈判。

2. **先问三件事，再给数字。**
   条数（决定 F02 还是 F06）、投屏分辨率（决定适配工量）、有没有真实数据接口（决定 1~2 天还是 0）。
   这三个答案不同，同一张效果图能差 3 倍工时。

3. **把「不改」写进范围。**
   明暗双主题、多分辨率、视频导出——这三项是最常见的「顺便加一下」。提早就这么说：
   > 「套餐②只保暗色单分辨率。亮色主题 +1 天，每多一个分辨率 +0.5 天，导出视频 +1 天。」
   说在开工前是加钱，说在验收时是吵架。
