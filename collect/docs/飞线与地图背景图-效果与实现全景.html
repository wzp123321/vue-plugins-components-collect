01飞线：14 种效果

按「视觉上能被区分的差异」排列，从最朴素到最复杂。每一种都写了它在各技术栈里怎么做、贵不贵、坑在哪。

F01静态弧线

两点之间一条固定的弧，不动。像航线图，一眼看完所有连接关系。

three.js QuadraticBezierCurve3 取点 → TubeGeometry 或自建三角带
echarts series-lines 不配 effect
deck.gl ArcLayer 一行搞定

成本极低可上千条适合截图汇报
F02彗星拖尾 本项目

一个白热头带着一条由亮到暗的尾巴沿弧线跑，循环。大屏上最经典、最「有速度感」的效果。

three.js 三角带 ribbon + 逐帧重写顶点色（behind = p - t，幂次衰减）；
或 shader 传 uTime，顶点 attribute 存弧长参数
echarts effect: { show, period, trailLength, symbol: 'circle' }

成本中每帧写顶点注意 dt 累加
F03流动虚线

整条线是均匀虚线，虚线沿线滚动。像「数据正在传输」，比彗星安静，适合同时画很多条。

three.js LineDashedMaterial + 动画 dashOffset，别忘了先调 computeLineDistances()
shader mod(uv.x * repeat - uTime) 控制 alpha

成本低可批量适合链路拓扑
F04双向对开

两端各有一个头往中间跑。用来表达「双向同步」「互为备份」这种业务语义。

做法 同一条曲线建两条 ribbon，speed 一正一负；或一条 curve 上挂两个 head，相位差 0.5

成本低顶点翻倍
F05管道流光

线有体积、有明暗过渡，光像在管道内部流。特写镜头很贵气，但线一多就糊。

three.js TubeGeometry + MeshStandardMaterial（要灯光）
流动 滚动贴图 map.offset.x -= speed，或滚 alphaMap

成本高三角面 ×8~16只适合少量
F06粒子飞线

一串小光点沿路径飞，像星尘或数据碎片。几千条线同时跑也不卡，是「量大」时的唯一出路。

three.js 一个 Points 装所有粒子，attribute 存「路径编号 + 起始进度」，顶点着色器里按 uTime 算位置
查表 曲线采样点打包成 DataTexture，shader 里 texture2D 取坐标

极省1 次 draw call点大小要注意 pixelRatio
F07渐变描边线

线本身从暗到亮渐变，静态。没有动效但有「方向感」——亮的一头是终点。

three.js vertexColors: true + 逐顶点写色（三角带左右两顶点同色）
SVG / Canvas 直接 linearGradient / createLinearGradient

成本极低常与 F02 叠加
F08泛光叠加（Bloom） 本项目

线周围有一圈柔和光晕，暗底上「炸」出来。同一个线宽，加不加 bloom 是两个档次的观感。

three.js EffectComposer + UnrealBloomPass；把发光物体放进单独 layer，只泛这一层
低成本替代 同路径再画一条宽而透明的 ribbon（假光晕），省掉全屏后处理

成本中全屏后处理会让 canvas 不透明
F09端点涟漪

起点/终点一圈圈扩散的环，像雷达波。强调「这里是源头」，一句话就能让产品理解发生了什么。

three.js RingGeometry 三个实例错相位，动画 scale + opacity
2D Canvas arc() 每帧重画 / CSS @keyframes 放大

成本低别进 bloom 层
F10数据驱动的粗细 / 颜色

流量大的线粗、告警的线红。这时飞线不是装饰，是「数据」本身——产品通常到后期才提这个需求。

做法 把数值写进顶点 attribute，shader 里映射半宽与色相；CPU 端则在 widthAt(index) 里按值返回
坑 不要用 mesh.scale 改粗细，会把整条线等比放大、端点偏移

成本中色板要可配置L3 级需求
F11逐段生长（进出场）

线从起点「长」到终点，长完停住或再退回去。进场动画必备，比整条线闪一下自然得多。

ribbon 只画前 progress × N 个采样点，或 geometry.setDrawRange(0, count)
SVG / CSS stroke-dasharray: L + dashoffset: L → 0

成本低常与层级下钻配合
F12遮挡关系（贴地 / 浮空）

线被山体挡住 = 有真实空间感；线永远压在最上层 = 哪条都不漏但显得「贴纸」。这是一个产品能直接感知、但几乎不会主动提的选项。

被遮挡 depthTest: true + depthWrite: false（这个组合最稳）
永远可见 depthTest: false，渲染顺序 renderOrder 调高

零成本建议默认遮挡
F13多层拖影

同一条路径上错开几个相位、几个速度，形成「余晖」。单看是作弊，观感是「更贵」。成本是线数翻倍。

做法 同一 curve 建 3 条 ribbon，speed 与 phase 略有差异，透明度递减

成本 ×3适合主视觉单线
F14球面大圆弧（Globe）

在球体上两点之间走大圆航线并抬升高度。数据是「全球」量级时才有意义，国内项目基本用不到。

Cesium PolylineGlowMaterialProperty 开箱即用
deck.gl ArcLayer / TripsLayer
three.js 球面插值 + 法线方向抬升

引擎内置只在全球化场景用

02飞线的 6 个拆解维度

上面 14 种是「常见组合」。真要定制时，把一条飞线拆成下面 6 个维度逐项勾选，勾完方案就定了，也就能估工了。 维度表的最大用处：指出哪些组合是**做不出来**或**很贵**的。

维度可选项技术后果
1 路径形状 直线 / 高空弧（二次贝塞尔）/ 贴地弧 / 多段折线（经中转）/ 绕行螺旋 全部走同一条「采样点数组 + 等弧长」管线，形状可换，成本不变。只有「绕开障碍」需要碰撞或手工控制点，会变成 L3
2 截面样式 1px 原生线 / 三角带 ribbon / 管道 tube / 粒子串 / 贴图 plane 这是分水岭。选 1px 就无法加粗；选 ribbon 才有宽窄与收细；选 tube 才有明暗体积但贵 8 倍
3 运动方式 静止 / 彗星拖尾 / 匀速虚线 / 双向对开 / 整段呼吸 / 逐段生长 都在「一个 0~1 的进度变量」上做文章，可叠加（彗星 + 生长 = 进场后先长出来再跑）
4 颜色语义 单色装饰 / 两端渐隐 / 按数值映射 / 按状态（红绿）/ 加法发光 「按数值」和「按状态」要改数据结构（每条线带 value / status），是需求变更不是样式调整
5 附加元素 头部光点 / 端点涟漪 / 沿线粒子 / 标签数值 / 多条拖影 每加一种就多一层 draw call，通常 ≤ 3 层还能稳住 60 帧
6 相机与深度 始终面向相机 / 固定朝向 / 被遮挡 / 永远浮顶 / 像素下限 只有 3D 场景才有这一维。2D 地图（echarts）没有，所以 2D 做不出「线从地图背后穿过」的观感
勾选规则：把产品的话翻成 6 个维度的勾，如果某一维他答不上来，就给默认值并写进备注。 6 个维度全部确定，工时就能估出来；有 1 个空着，报价一定会翻车。

03三条硬限制（说给产品听的技术边界）

这三条不是「优化空间」，是物理限制。提前说清楚，别在验收会上才发现。

限制一 · WebGL 的线宽被锁死在 1 像素。
LineBasicMaterial.linewidth 在绝大多数平台（Chrome / Windows / 移动端）都会被驱动忽略，永远 1px。 想让线变粗，只能用三角带或管道这类「面」去模拟「线」。所以「线再粗一点」这句需求， 在 1px 方案里是无法实现的，必须换实现方式。
限制二 · 线宽是「世界单位」，镜头一远就断。
条带宽度写的是地图尺度（比如 0.66 个地图单位）。镜头拉远后，它在屏幕上只剩 0.7 个像素， 不到 1 像素的线显卡画一半丢一半 → 看起来一截一截断掉，拖尾和轨道断点还不在同一位置，所以像错位。
解法是给线宽加「屏幕像素下限」（拖尾 ≥ 2px、轨道 ≥ 1.2px、光点 ≥ 6px）。拉近时下限不生效，观感不变。
限制三 · 开了后处理，细线更容易闪。
EffectComposer 的 renderTarget 默认没有 MSAA（samples: 0）， 亚像素宽度的几何覆盖率不稳定。可以设 samples: 4 开抗锯齿，但显存和带宽都会涨。 稳妥做法是像素下限（限制二）+ 后处理只覆盖发光层。

04背景图：三层，21 种

背景不是一个东西，是三层叠出来的：屏幕层（钉在窗口上，不跟相机）、 场景层（躺在三维世界里，跟着透视动）、后处理层（不改内容，只改「看起来多高级」）。 真实的大屏通常是「屏幕层 1~2 张 + 场景层 2~3 个 + 后处理 2 个」的组合。

4.1 屏幕层 · 不跟相机 CSS / DOM · 性能最好

B01纯色 / 渐变

最省事的一种。中心亮、四周暗的径向渐变，就能有「聚光」感，成本几乎为零。

实现 radial-gradient() / linear-gradient()，多层叠加就是一张「氛围图」

零成本无素材依赖本项目兜底方案
B02网格线

最直白的「科技感」。间距越小越密越像电路板，越大越克制。要压在飞线下面，不能抢戏。

实现 两条 repeating-linear-gradient（横 + 竖）+ background-size 控制格距

零成本注意透明度 ≤ 0.08
B03点阵 / 六边形阵列

比网格更「柔」，远看是一片质感，近看才有点。适合放在数据面板背后当底纹。

实现 radial-gradient(circle, c 1px, transparent 1px) + background-size: 13px；六边形用 SVG pattern

零成本
B04静态图片 本项目

设计稿 / 卫星图 / AI 生成的纹理。观感上限最高，但会带来裁切、体积、版权三个问题。

实现 background-image: url() + background-size: cover + background-position
必做 叠一层暗角（中心 0.04 / 边缘 0.34），否则飞线看不清；超宽屏要改锚点（如 center 42%）

零成本注意版权WebP ≤ 300KB
B05多层叠加 + 混合模式

同一张图，换个 blend-mode 就从「灰扑扑」变「有情绪」。给底图统一着色最省事的办法。

实现 background-blend-mode: screen / overlay / soft-light；对元素间用 mix-blend-mode

零成本做旧 / 统一色调
B06噪点 / 颗粒

大屏上「高级不高级」的分水岭。纯色渐变看起来像 PPT，加 3% 噪点就有「胶片 / 材质」感。

实现 内联 SVG feTurbulence 做 data URI，opacity 0.03~0.06 + mix-blend-mode: overlay

零成本最划算的一招
B07动态渐变（旋转 / 位移）

用 conic-gradient 慢速旋转，背景会有「能量在流动」的错觉。成本极低，但看久了会腻。

实现 conic-gradient + @keyframes rotate（14~20s 一圈，再快就晃眼）
省电 prefers-reduced-motion 时降级为静态

零成本注意动效疲劳
B08视频背景

最「燃」，也最容易被换掉。作为背景只能当氛围，不能承载信息。

实现 <video autoplay muted loop playsinline> + object-fit: cover
代价 10s 的 1080p 循环 ≈ 2~6MB；要预加载首帧，否则开场黑屏

体积大素材常被换移动端慎用
B09Canvas 程序化生成

JS 现画：同心圆、等高线、随机粒子、随数据变化的纹理。没有素材也能做出「量身定制」的感觉。

实现 <canvas> 2D 绘制 → toDataURL() 当背景，或直接挂成 three.js 的 CanvasTexture

要写绘制逻辑无素材依赖本项目底板用这个

4.2 场景层 · 跟着相机走 three.js · 有透视，会随视角变形

B10大平面贴图

地图下面铺一块巨大的平面，贴上纹理。镜头一动，它有近大远小的透视 —— 这是和 CSS 背景最本质的区别。

实现 PlaneGeometry + MeshBasicMaterial({ map })，放在地图 z 之下，depthWrite: false
坑 和平面的 z 太近会 z-fighting，要拉开 0.5 以上

成本低1 个 mesh
B11程序化 Canvas 纹理底板 本项目

同心圆 + 放射刻度 + 中心光晕，1024 画布现画，转成纹理贴到平面上。看起来像「雷达盘」，和地图是同一套科技语言。

实现 2D canvas 画环 → new THREE.CanvasTexture(canvas) → 贴 PlaneGeometry(MAP_EXTENT × 3.4)
关键 暗主题 AdditiveBlending（发光）；亮主题必须换 NormalBlending，否则加法混合在浅底上等于越叠越白、网格直接消失

成本低无素材内圈要留白
B12网格辅助地面

极简的方格地面。零素材、零设计，但立刻有「三维空间」的参照系。

实现 GridHelper / PolarGridHelper，一条语句；或用 repeating-linear-gradient 贴平面（更可控）

零成本容易显得「没做设计」
B13天空盒（Skybox）

六面立方体贴图把整个场景包起来，360° 无死角。沉浸感最强，也最重。

实现 CubeTextureLoader + scene.background = cubeTexture
代价 6 张 1024 图 ≈ 6~12MB；室内大屏基本用不上

体积大适合外景 / 星球
B14渐变天空球

一个巨大的球，内壁刷渐变。比天空盒轻得多，程序化生成，颜色随时可调。

实现 SphereGeometry(1000) + side: BackSide + 自定义 shader 按 y 混色

成本低可程序化
B15星空 / 粒子背景 本项目

一圈闪烁的星点铺在地图外围。用的是「一次 draw call 全部星星」的做法，520 颗几乎不耗性能。

实现 Points + 顶点 attribute aPhase，shader 里 pow(sin(uTime + aPhase), 12) 做闪烁
坑 星点用固定种子的 PRNG 生成，否则每次热更新星空会「跳一下」；亮色主题要关掉，白星在浅底上像脏点

极省1 次 draw call
B16雾效 / 深度衰减

远处的物体自然淡进背景色里，边缘不再「硬切」。最廉价的「深远感」，很多人有但说不出是什么。

实现 scene.fog = new THREE.FogExp2(color, 0.0012)；注意 雾会让飞线远端变淡，要同步调线宽

零成本一行代码
B17真实地球（球体 + 卫星图）

用真实卫星影像贴球。地理可信度最高，但「中国地图」项目基本用不到——它是全球叙事才需要。

实现 SphereGeometry + 卫星图 + 法线贴图 + 平行光；进阶加云层、夜景灯光贴图

成本中素材 4~20MB

4.3 后处理层 · 不改内容，只改质感 EffectComposer · 决定「高级感」的最后一层

B18泛光 Bloom

所有比阈值亮的东西都会「发光溢出」。飞线、光点、文字都靠它变得像真的在发光。

实现 UnrealBloomPass(resolution, strength, radius, threshold)
坑 自写的混合 shader gl_FragColor = base + bloom 会把 alpha 变成 1，导致 canvas 不透明、下面垫的 CSS 背景透不出来 —— 要写成 vec4(base.rgb + bloom, base.a)

全屏后处理分辨率越高越贵
B19暗角 Vignette

四角压暗，视线被推到中间。相机和电影都在用，是最不占成本的「专业感」。

CSS 版 radial-gradient(circle, transparent 40%, rgba(0,0,0,.55)) 盖一层
后处理版 屏幕四边形 + 距离衰减 shader

零成本CSS 就能做
CHROMATIC
B20噪点 / 色差（Glitch）

轻微的红蓝分离 + 颗粒，科幻片的味道。做过了就是廉价赛博朋克，做轻了很高级。

实现 后处理 RGBShiftShader；CSS 版用 text-shadow 双色偏移 + 噪点叠加

需后处理克制使用
B21色调映射 / 色彩分级

把所有颜色统一到一套「胶片曲线」里。单看一张图没感觉，叠在一起就知道「为什么专业项目颜色不脏」。

实现 renderer.toneMapping = THREE.ACESFilmicToneMapping + toneMappingExposure；CSS 版可整体加 filter: saturate() contrast()

零成本一行开启

05效果 × 代价对照

给产品看的「价格牌」。同样叫「飞线好看一点」，走 F02 是半天，走 F05 + F08 + F13 是三天，还得配显卡。

效果工作量性能什么时候值得花可以砍掉的因素
F01 静态弧线0.5 天极好汇报型大屏，截图和录屏为主—
F02 彗星拖尾1~2 天好（≤ 300 条）对外演示的主视觉，默认首选拖尾长度可调，不影响结构
F03 流动虚线0.5 天极好链路/管线类，条数多—
F05 管道流光2~3 天差只有一条主线的特写镜头线一多就必须放弃
F06 粒子飞线2~3 天极好上千条，或者做「数据雨」需要 shader，改需求成本高
F08 Bloom 泛光1 天中暗底大屏，几乎必加可用「假光晕」替代，省一半
F10 数据驱动粗细1~2 天无影响飞线承载业务指标数据结构要改，后期加最贵
B04 静态图片底图0.5 天 + 找图极好有设计资源或能授权素材没有就退 B01 + B06
B06 噪点0.2 天极好任何想「不像 PPT」的项目—
B08 视频背景1 天 + 素材差发布会、开场素材常被否，慎选
B13 天空盒1 天 + 素材差全球/星球叙事国内地图场景不需要

06四套现成配方

真实项目不选「一种效果」，而是选一套组合。下面四套都能直接照着做，把它们当菜单给产品选。

① 科技冷蓝大屏

  • 底：B01 深蓝径向渐变 + B02 网格 + B06 噪点
  • 场景：B11 同心圆底板 + B15 星空 + B16 雾
  • 飞线：F02 彗星拖尾 + F08 bloom
  • 收尾：B19 暗角 + B21 ACES
  • 代价：约 4~5 天，性能中上

② 卫星实景风

  • 底：B04 卫星图 / 航拍图（务必先确认授权）
  • 场景：B10 大平面贴图 + B16 雾效
  • 飞线：F14 大圆航线 + F09 端点涟漪 + F12 遮挡
  • 收尾：B21 色调映射（让实景和 UI 同色温）
  • 代价：图片素材是大头，代码 2~3 天

③ 极简汇报风

  • 底：B01 纯色 + B03 极淡点阵
  • 场景：不要（关掉三维装饰层）
  • 飞线：F01 静态弧线，或 F03 很慢的虚线
  • 收尾：不加 bloom，不加暗角
  • 代价：1 天。打印、投屏、录视频都清楚

④ 值班监控风

  • 底：B01 深灰（不用图、不用网格）
  • 场景：只在必要处留一层淡网格
  • 飞线：F10 数据驱动粗细 + F03 虚线；不跑彗星（看久了累）
  • 收尾：关 bloom、关噪点，保证文字对比度
  • 代价：2 天。信息优先，长期盯着不疲劳

08怎么拿这一页跟产品对

五个动作，一次会就能收敛。顺序不要换。

步骤你说什么目的
1 「先定像不像：你扫一眼这 14 张，圈出 2~3 个你想要的。」 把「感觉」压成离散选项。圈不出来的，说明他自己也没想清楚，这时候别报价。
2 「这几条线代表什么数据？大概多少条？」 决定 F02 还是 F06，差 3 倍成本。
3 「投屏多大、观众离多远、现场会不会有人缩放？」 决定像素下限、线宽档位、要不要锁机位。三条里漏一条，验收必吵。
4 「背景这块，它跟不跟着地图转？它是主角还是配角？」 一句定架构（CSS 还是场景层），一句定视觉权重（压不压暗）。
5 「我们从① ② ③ ④ 里选一套，剩下的效果砍掉，行吗？」 收口。必须让他亲口说「砍掉」，否则后期会一条条加回来，成本翻倍。
一句话记住：产品要的是「效果」，你要交的是「参数」。 这一页做的就是中间那层翻译——他指一个格子，你翻到一个编号，编号后面写着怎么做、多贵、有什么坑。 没有编号的需求，一律不接。

最终方案 = 路径（弧/直/贴地） × 截面（ribbon/tube/粒子） × 运动（彗星/虚线/静态）
           × 颜色语义（装饰/数值/状态） × 附加层（涟漪/光点） × 相机策略（遮挡/像素下限）
