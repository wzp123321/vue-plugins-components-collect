P0-1全局请求拦截器从未生效

证据
src/services/request.ts 在模块顶层注册 axios.interceptors，但全仓没有任何文件 import 它 —— grep -rn "services/request" src 只命中一处注释和一处 demo 代码字符串；src/main.ts 也没有副作用引入。
连带
它设的 config.baseURL = import.meta.env.VITE_BASE_URL 也从未跑过，而 VITE_BASE_URL 在 .env 里根本不存在（只有 VITE_DEV_SERVER_PORT / VITE_PROXY_URL / VITE_TIME_OUT）。
还有
config.timeout = import.meta.env.VITE_TIME_OUT as number —— env 值是字符串 "60 * 1000"，as number 只是类型断言，运行时仍是字符串。
改法
① 改成显式实例导出 export const http = axios.create({ timeout: Number(import.meta.env.VITE_TIME_OUT) || 60000 })，业务侧 import 使用，别依赖模块副作用；② .env 只写数字 VITE_TIME_OUT=60000；③ VITE_BASE_URL 要么补进 env 文件，要么删掉这行。
借鉴
HLMS hlms-bi-front/src/apis/DatasetApi.ts 用 ApiClientFactory.client() 显式取实例；hlms-data-report-app-front/src/utils/request/index.ts 也是 ApiClientFactory 单例。副作用注册在微前端 / 多入口场景下极易漏掉。

P0-2两个 request.ts，职责完全相反

文件实际内容
src/utils/request.tsAES-GCM 加密 + 授权串生成（FEncrypto / FGetAuthorization / getRandomSixNum）—— 一行请求代码都没有

改法
utils/request.ts → utils/auth-sign.ts（或 crypto-sign.ts）；services/request.ts → services/http.ts。

HLMS 的命名一律「见名知义」：mega-vision/packages/shared/src/request-crypto.ts（加密）、hlms-dgmp-nodejs/src/utils/http.ts（请求）。

证据
