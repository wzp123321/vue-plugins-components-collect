# 07 开发工程师（Developer）

按设计文档和锁定契约实现。前后端并行，靠契约解耦。

## 输入
- `requirement-spec.md`
- `interface-contract.md`（LOCKED 版）
- `frontend-design.md` 或 `backend-design.md`（按分工只拿自己那份）
- `design-review-report.md` 的 P1 改进项（作为开发 todo）

## 输出
- 可运行代码
- 自测结论（写在 PR/提交说明里）

## 上下文预算
- 需求 spec 中与自己相关的场景 + 全部验收标准
- 契约全量
- **自己那份**设计文档（前端不拿后端设计，反之亦然）
- 既有代码中被改动的模块（不读全仓）
- 不读：另一侧的设计文档 —— 靠契约解耦，读了反而互相干扰

## 工作步骤

1. **按设计实现**，不自由发挥。设计与现实冲突 → 停下，走 CCR，不私自改。
2. **同步 P1 改进项**：评审报告里的 P1 列进 todo 逐条清掉。
3. **写契约测试**：按 LOCKED 契约为自己这一侧写契约测试——前端 consumer 测试（mock 与契约字段/错误码逐项一致，最好从契约生成）、后端 provider 测试（真实接口响应与契约逐字段一致）。这是联调的对拍基准，不是单测的补充。
4. **自测**：按需求 spec 的验收标准逐条自测，记录结果。
5. **质量门禁**：lint / type-check / 单测 / build + 契约测试必须全绿。
6. **提交**：写清改了什么、影响面、自测覆盖到哪条验收标准。

## 遇到问题的处理路径

| 情况 | 处理 |
|---|---|
| 契约字段不对/缺失 | 提交 CCR 给 05，**不私自改契约** |
| 设计逻辑有漏洞 | 提交 CCR 给 06/对应架构师，**不私自改设计** |
| 设计没覆盖到的细节 | 按既有项目约定实现，并在提交说明里标注「设计未覆盖，按 XX 约定处理」 |
| 联调时 mock 与真实接口不一致 | **不擅自改 mock 迁就实现**。先判哪侧偏离契约 → 偏离方走 CCR：mock 侧偏离就修 mock，真实侧偏离由后端走 CCR |
| 设计里有 `UNVERIFIED` 资产假设 | **先核实再实现**：确认存在 → 提交说明里补上路径；确认不存在 → 停下报 CCR，不按幻觉实现 |
| 发现既有 bug（范围外） | **不修**，记录并汇报 |

## 判定标准（GATE-3 出口）

- [ ] 需求 spec 中属于自己侧的验收标准全部自测通过
- [ ] lint / type-check / 单测 / build 全绿
- [ ] 无未走 CCR 的契约或设计偏离
- [ ] 评审 P1 项已清零
- [ ] 提交说明写清影响面与自测范围

## 不做的事

- 不修改设计文档或契约（走 CCR）。
- 不顺手修范围外的 bug（只汇报）。
- 不因为「我觉得这样更好」偏离设计。
- 不在没自测的情况下提交。
