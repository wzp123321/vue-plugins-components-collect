# 08 验收自测（QA / Acceptance）

按需求 spec 的验收标准逐条验证。**只报缺陷，不修 bug。**

验收分两层：**L1 契约层（08a）** 与 **L2 UI 层（08b）**。
两层都过才能写 `PASS`；只过契约层只能写 `CONTRACT_PASS`，**不得交付**。

## 输入
- `requirement-spec.md`（验收标准是唯一判据）
- `interface-contract.md`（验证接口是否符合契约）
- `frontend-design.md` + `backend-design.md`
- 可运行的产物

## 输出
- `acceptance-report.md`（模板见 [`../templates/acceptance-report.md`](../templates/acceptance-report.md)）
- 报告内 L1 / L2 结论分开记录，`PASS` 需两层同时成立

## 上下文预算
- 需求 spec 全量（尤其验收标准章节）
- 契约全量
- 两份设计文档（用于判断是否偏离）
- 不读：实现代码细节 —— 验收是**黑盒**的，看行为不看实现

## 验证层次

### L1 · 契约层（08a）
验接口语义，不看界面：

1. **逐条验收标准**：Given/When/Then 一条条过，记录 PASS / FAIL + 证据
2. **契约符合性**：实际接口与契约是否一致（字段名、类型、错误码）
3. **异常路径**：需求里写的异常场景 + 常见异常（空数据、超时、并发、权限不足、边界值）
4. **非功能**：需求里量化过的性能指标是否达标

### L2 · UI 层（08b）
验真实界面行为——**L1 全绿不代表功能可用**：

1. **交互时序**：防抖/节流是否生效、loading 出现与消失时机、按钮防重入、跳转与回显
2. **状态渲染**：空态、错误态、无权限时按钮**不渲染**、长文本/极端数据不破版
3. **流程闭环**：完整用户旅程走一遍（新增 → 列表可见 → 编辑 → 删除 → 再查不存在）
4. **可用性速查**（快速过，不逐项写证据，发现问题才展开）：核心流程可否纯键盘完成（Tab/Enter/Esc）；错误提示是否可操作（说清怎么了 + 下一步做什么，不是「操作失败」）；loading 出现/消失是否引起布局跳动；破坏性操作有确认且成功后有反馈；空状态有引导而非一片空白
5. **回归**：受影响既有功能是否正常

两层结论分开记录。L2 未执行（如无 UI 产物）必须显式写「未验证 + 原因」，不得默认算过。

## 缺陷分级

| 级别 | 定义 | 处理 |
|---|---|---|
| `BLOCKER` | 核心验收标准不通过 / 崩溃 / 数据错误 | 按**根因分层**回退，不默认回 Phase 5 |
| `MAJOR` | 次要验收不通过 / 异常路径缺失 / 契约偏离 | 按**根因分层**回退 |
| `MINOR` | 体验瑕疵、文案错误 | 可带病交付，列进 backlog |
| `NIT` | 主观建议 | 不强求 |

## 根因分层与回溯（报 FAIL 前先判根因，再定回退阶段）

| 根因 | 判据 | 回退到 |
|---|---|---|
| 契约没定义 / 定义错 | 缺陷源于契约缺失，或契约本身就写错了 | Phase 2（05 改契约 + 通知双方） |
| 设计漏了 / 设计错了 | 实现符合设计，但设计没覆盖这个场景 | Phase 3（对应架构师） |
| 实现偏离设计 | 设计写了，代码没做到 | Phase 5（07 改代码） |
| 需求本身错了 | 按 spec 做对了，但 spec 的要求是错的 | Phase 1（01 + 02，重新冻结） |

不分级会导致「用修代码的方式修设计问题」，越修越歪。根因判据写进缺陷清单，编排者按它派 handoff。

## 结论

- L1 + L2 均无 BLOCKER / MAJOR → `PASS`，进 GATE-4
- 仅 L1 过，L2 未过或未验 → `CONTRACT_PASS`，**不得交付**
- 有任一 BLOCKER / MAJOR → `FAIL` + 缺陷清单，按根因分层回退

## 缺陷清单格式

```markdown
### [BLOCKER] <一句话描述>
- 对应验收标准：spec §X 第 n 条
- 复现步骤：1. ... 2. ... 3. ...
- 期望：<spec 原文>
- 实际：<观察到的行为>
- 证据：<截图/日志/响应体>
- 影响范围：<哪些场景受影响>
- 疑似原因：<可选，仅供参考，不代替开发定位>
```

## 不做的事

- **不改代码**。修验一体会掩盖问题。
- 不降低标准迁就实现（「这样也能用」不是 PASS 的理由）。
- 不验收需求外的东西（发现范围外问题 → 单独汇报，不计入结论）。
- 不在没有证据的情况下写 PASS（「应该没问题」无效）。
