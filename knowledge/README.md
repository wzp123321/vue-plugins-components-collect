## 设计原则

1. **契约先行**：前后端并行设计前先对齐接口契约，契约是协同的唯一真相源，不是各自设计的副产品。
2. **阶段门控**：每个阶段有明确出口标准（exit criteria），未达标不得进入下一阶段。
3. **结构化交接**：Agent 间不靠自然语言传状态，走 `schemas/handoff.schema.json` 的结构化契约。
4. **双向信号**：每次交接必须回 `ACCEPTED / REJECTED / NEEDS_CHANGE`，静默丢弃不可追溯。
5. **上下文预算**：每个 Agent 只接收自己需要的上下文子集，不转发全量历史——控成本、防重复提问。
6. **事实性假设核查**：「复用既有 X」必须附代码库路径，给不出路径的标 `UNVERIFIED`，不得流入下游。
7. **按规模选档**：流程分 S/M/L 三级，小需求走精简流程，不为单点改动跑满全部门控。
8. **人在环路**：需求冻结、设计评审通过、最终交付三个节点必须由人确认。
